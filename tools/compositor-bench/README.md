# 合成器基准（compositor bench）

"only around arrows" 本地合成器（`src/lib/localEdit.ts`）的离线回归测试。不调用任何模型：
用脚本**模拟模型的回答**，再检查合成器保住了多少想要的改动、有没有动到不该动的像素。

改合成器的任何阈值或步骤之前和之后都跑一遍。

## 准备（一次）

```bash
# 仓库根目录
npm install
npm install --no-save playwright && npx playwright install chromium   # 浏览器，仓库本身不依赖它

# Python 3.11+
python3 -m venv .venv && .venv/bin/pip install -r tools/compositor-bench/requirements.txt
```

`esbuild` 随仓库的依赖一起装好了。样例照片不在仓库里，`sim.py` 直接读 scikit-image 包自带的
`astronaut.png`、`coffee.png`、`chelsea.png`。

## 使用

```bash
cd tools/compositor-bench
python sim.py                      # 生成 52 个用例到 cases/（约 6 分钟，只需一次）
node run.cjs before                # 用当前源码跑一遍，结果写到 out/before/
python metrics.py before           # 打分；有用例不通过时退出码为 1

# 改完代码后
node run.cjs after && python metrics.py after
```

- `node run.cjs <标签> [名字过滤…] [--maps]`：每次运行都会重新打包当前源码。
  `--maps` 另外输出检测阶段的几张图，用来看一块内容是在哪一步被留下或被取走的：
  `map-strong.png` 强变化、`map-weak.png` 弱变化、`map-joined.png` 并入的部分、
  `map-first.png` 各箭头最初认领的部分、`map-outline.png` 被认作"只在一张图里有的轮廓"的细线（只在给了物体范围时才找）、
  `map-outlined.png` 凭物体范围取走的部分、`map-grown.png` 最终区域。
- 每个用例的 `out.json` 里有逐箭头的统计（`stats`）。给了物体范围时多一项 `still`：
  `[范围内淡变化部分里原图细节所占比例, 这些细节里强度保持不变的比例]`（只看离明显变化 3 px 以外的地方）。
  后者 ≥ 0.47（且前者 ≥ 0.01、淡变化至少 150 px）说明那里的东西"还在，只是被调了色"
  （比如一张没给保护框的脸），这个范围就不采用；`info.extentsUsed` 记录每个箭头的范围是否被采用。
- `python sim.py <场景 id…>` 只重新生成指定场景。
- `cases/`、`out/`、`.build/` 不入库。

## 用例

每个用例一个目录：

| 文件 | 内容 |
|---|---|
| `orig.png` | 被编辑的原图 |
| `ideal.png` | 原图加上**只有**想要的那处改动（标准答案） |
| `result.png` | 模拟的模型回答：把 `ideal` 整张"重画"一遍 |
| `gt.png` | 改动所在位置（软蒙版） |
| `protect.png` | 必须保持原样的区域（脸、另一只眼睛等） |
| `meta.json` | 箭头位置 `marks`（0–1 的比例）；期望 `expect`：`ok` / `reject` / `any`；可选 `left_max`（允许残留的百分比，默认 15）；可选 `options` |

`meta.json` 的 `options` 就是应用在两张图之外交给合成器的东西（`LocalEditOptions`）：

- `extents`：每个箭头所指物体的范围框（"find the object" 开关打开时由 Gemini 给出）；
- `guarded`：不许凭轮廓或范围取走的区域（脸）；
- `touches`：用户在结果上点选的补取 / 还原点。

`sim.py` 里的 `SCENARIOS` 定义了 30 个场景：

- 移除物体、换色、提亮、加斑块；单箭头和双箭头；紧贴画面边缘；模型没改或改错了地方；
- `S-arm`、`S-arm-thin-line`：一条和身后内容同色的"手臂"被删掉（`smooth` 把照片磨平，`objects` 是原图里有、
  标准答案里没有的东西）。内部新旧几乎一样，明显不同的只有轮廓。**不给物体范围时，这类物体不会被整块取走，
  这是有意的**（见下面"为什么轮廓不单独作数"），所以这两个场景写的是 `expect='any'`、`left_max=100`；
- `S-arm*-found`：同样的物体加上范围（场景里写 `found=True`），必须取干净，包括只有发丝粗细轮廓的、
  以及只有轮廓不同、箭头处毫无变化的；
- `A-hood-ring-found`：范围框把脸也框了进去，脸在 `guarded` 里（`guard=True`），必须保持原样；
  `A-hood-ring-found-unguarded`：没给脸的保护框，也必须保持原样；
- `A-earring-in-guard`：箭头指的东西本身就在保护框里（耳钉在脸的框内，场景里用 `guard_boxes` 写框），
  这个东西仍然要完整改掉；
- `C-remove-spoon-touched`：自动部分留下的勺柄，由三个补取点取走（`touches`）。

`repaint()` 模拟模型重画整张图带来的偏差，分三档：

| 级别 | 平移 px | 缩放 | 扭曲 | 噪声 | 色调 | JPEG | 旋转° |
|---|---|---|---|---|---|---|---|
| `mild` | 3.0 | 0.004 | 0.6 | 2.0 | 0.025 | 90 | – |
| `strong` | 6.0 | 0.009 | 1.3 | 4.0 | 0.05 | 82 | – |
| `warped` | 6.0 | 0.018 | 1.5 | 3.0 | 0.04 | 85 | 0.6 |

加新用例：在 `SCENARIOS` 里加一项（坐标用照片原始像素，`scale` 是放大倍数），再 `python sim.py <id>`。

## 指标

| 列 | 含义 | 期望 |
|---|---|---|
| `pass` | 接受/拒绝与 `expect` 一致，`protect` 为 100，并且 `left` 不超过允许值 | 全部 True |
| `kept` | 想要的改动保住了多少（1 = 全部） | 越高越好 |
| `left` | 改动里明显不同的像素中，仍与原图逐位相同的比例（没被取走的部分） | ≤ `left_max`（默认 15） |
| `extra%` | 改动范围之外（外加短边 5% 的余量）被替换的像素占全图的比例 | 接近 0 |
| `protect` | 受保护区域里与原图逐位相同的比例（不计紧贴改动的那一圈） | **必须 100** |
| `strict` | 同上，但只留很窄的余量 | 越高越好 |
| `seam` / `seamGrad` | 接缝外侧 ±3 px 带上相对标准答案的颜色 / 梯度误差 | 越低越好 |

基线（2026-11-16）：52 / 52 通过。已登记的已知限制（场景里用 `left_max` 或 `expect='any'` 标出）：

- `C-remove-spoon`：被杯沿隔开的勺柄只取到一部分（残留约 30%）；
- `S-arm`、`S-arm-thin-line`：不给物体范围时只取到明显变化的部分（残留 18%–88%），见下一节。

## 为什么轮廓不单独作数

曾经试过让合成器在没有物体范围时也凭"只在一张图里有的细轮廓"把整个物体取走。独立审查用 110 个针对脸的用例
把它攻破了：箭头指着脸上的痣、发夹、眼镜、发带时，只要模型顺手抹掉或挪动几条细纹（法令纹、眼下纹、脸的轮廓线），
再把脸调亮 8–12 级，这些细纹就会被当成"物体轮廓"，被调色的皮肤被当成"物体内部"，半张脸被取走。110 例里 54 例
比没有这条规则时更差，而且两类情况的得分互相重叠，调阈值分不开。

所以现在的规则是：

- 没有物体范围时，行为与加入这些功能之前**逐字节相同**（上面 110 个用例已逐一比对）；
- 轮廓和淡变化只在 `options.extents` 给出的范围内作数，`options.guarded` 里的区域（脸）一律不取，
  哪一步都不行。例外只有箭头自己的物体落在保护框里的那部分：箭头尖核心范围内的明显变化；
  以及与框外物体"同一种变化"的部分（跟着头发一起换色的刘海、眼镜的其余部分），见 `ownInGuard`；
- 范围内的淡变化如果"还在，只是被调了色"，这个范围不采用。这是第二道防线，防的是模型没报出来的脸。
  它是兜底而不是保证：脸很小（整图 512 px 左右）或没有细节可看时它判断不了。
  带柔和阴影或半透明的物体也会被它判成"还在"，这时结果与不给范围时相同，不会更差。

同样的实验对"箭头在衣服上"也做过（54 例）：普通的换色、去补丁，这条规则不触发，脸不受影响；
但同色的"手臂"横在胸前时规则触发，9 例里有 7 例在模型改了脸上细线的情况下动到了脸（3,600–12,000 像素）。
所以问题不在于箭头是否指着脸，而在于规则一旦起作用就可能够到脸。

改动这几条之前，先重建那批攻击用例：箭头放在脸旁边或脸上的小东西上（痣、耳钉、发夹、眼镜、发带），
在脸上画几条细线，让它们在原图和回答里位置相差 7–10 px 或只在一边有，再给回答里的脸加 8–12 级的整体亮度偏移，
`protect.png` 盖住脸。然后确认：不给 `options` 时输出与改动前逐字节相同；给了范围和保护框时脸一个像素不变。

## 局限

这 52 个用例只是最小的一套。开发过程中另有三百多个针对性更强的用例（发丝、耳钉、痣、眼镜、孔洞、
缩放漂移、严重压缩等）没有入库。模拟的回答也不等于真实模型的回答：
通过基准是必要条件，不是充分条件。
